# Architecture

## Components
| Component | Role |
|---|---|
| `web` (Nginx) | Serves the React build, proxies `/api/` to the backend, security headers + CSP, 1 MB body cap. The only service published on the network. |
| `backend` (FastAPI) | Auth, RBAC, ingestion, search, alerts, incidents, rules, AI, response, audit, reports. |
| `worker` | Consumes Redis Streams; runs normalize -> dedupe -> detect -> alert/correlate -> index. |
| PostgreSQL | Users, assets, keys, rules, alerts, incidents, notes, investigations, response actions, audit. |
| Redis Streams | Buffer between ingestion and processing; consumer group, stale-claim recovery, retry, dead-letter stream, counters. |
| OpenSearch | Daily indices `sentinelx-events-YYYY.MM.DD`, explicit mappings (`dynamic: false`), hourly retention job. |

## Code layout (backend/app)
`api/` routes (thin) · `services/` business logic · `domain/` framework-free logic (normalizer, rule engine,
correlation, MITRE, AI analysis, response validation, query model, memory backends) · `infra/` Redis/OpenSearch
adapters · `models/` ORM · `schemas/` Pydantic · `workers/` pipeline · `core/` config, security, middleware.
Detection rules live outside code in `detection-rules/*.yml`. The domain layer imports no web/ORM packages, which is
why it is fully unit-tested.

## Event flow and guarantees
1. Collector posts a batch with `X-API-Key`. Each event is validated individually; bad events are rejected with a reason, good ones queued.
2. The server overrides `host.name/id` from the key's asset (a collector cannot impersonate another host; a mismatch is kept as `labels.reported_host`).
3. Worker order: normalize -> `store.exists` (duplicate gate) -> rule engine (idempotent per event id) -> alerts committed -> event indexed.
   A failure before indexing leaves the event un-indexed so retries redo everything; alert upsert ignores events it already has.
   After 3 attempts a payload goes to the dead-letter stream. Malformed events are quarantined there immediately. Nothing is silently dropped.
4. Alerts dedupe on `rule + group + time bucket`, keep rule id/version, up to 200 event ids and 50 evidence snapshots (so evidence survives index retention).
5. On alert creation, correlation looks for alerts from *other* rules within 600 s sharing (host AND user) or a non-public source IP. Result: an incident with a stored human-readable reason per alert.

## Detection rules
YAML, versioned, types `match` / `threshold` (count or distinct count) / `sequence` (N failures then success).
Operators: eq, ne, in, not_in, contains, contains_any, startswith, endswith, regex, exists, gt/gte/lt/lte; combinators all/any/not;
`exclude:` block for known-benign activity. API-created rules start **disabled**. Rules never use AI.

## Response safety
Allowlist of 4 actions with strict parameter validation (no shell, reserved test IPs only, no built-in privileged accounts);
registered lab-authorized assets only; dry-run on proposal; approver must hold `response:approve` and differ from the requester;
approval expires (30 min); atomic `pending -> approved` transition prevents double execution; adapter is `mock`; rollback; every step audited.

## Security model
See README. Authorization is enforced by `require(<permission>)` dependencies; roles map to permissions in `core/permissions.py`.
Object-level checks apply to saved hunts (owner only). The UI hides controls by permission but is not the security boundary.

## Deviations from the blueprint (and why)
| Blueprint | Implemented | Reason |
|---|---|---|
| Separate ingestion / normalization / detection / correlation workers | One worker process running the stages in order (modules are separate) | Simpler, avoids cross-worker state for the rule engine; fits lab scale. |
| `roles/permissions` tables | Role column + permission matrix in code | Fixed 4-role model; fewer moving parts. |
| `incident_events` / `alert_events` tables | `alerts.event_ids` / `evidence` JSON; `alerts.incident_id` + `correlation_reason` | One alert belongs to one incident; evidence kept with the alert. |
| `report_jobs` table | Reports generated on demand | No background jobs needed. |
| Detection rules only editable as files | Files seed the DB; engineers can edit via API (disabled until enabled) | Matches the "Rules" API in the blueprint. |
| `POST /ingest/events/batch` takes a normalized envelope | Takes `{event_id, timestamp, source_type, host, raw}` and normalizes server-side | Keeps source-specific parsing in one trusted place. |
| Alembic autogenerated migrations | Baseline migration calls `create_all` + PG audit trigger | Could not autogenerate against a live DB while authoring. |
| ECS via OpenSearch ISM for retention | Worker deletes expired daily indices | No ISM policy bootstrapping needed. |
| Playwright E2E | Not included | Could not run a browser in the build environment; shipping unrun tests was rejected. |
| 70% coverage / performance targets | Not measured | Targets only. |
| Redis consumer "recovery where practical" | `XAUTOCLAIM` of stale messages every 30 s + own-pending replay on restart | As specified. |
